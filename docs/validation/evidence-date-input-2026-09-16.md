# 원문 날짜 입력 개선 — 2026-09-16

## 바뀐 동작

Gemini가 `2026년 9월 23일 10:00`을 정확히 찾았지만 `semantic:null`로 반환하면, 이전 화면은 날짜 후보로 쓰지 못했다. 이제 공통 함수 `readEvidenceDateTime`이 저장된 원문 인용과 표시 값을 확인해 입력용 날짜를 만든다. AI 응답이나 저장된 fact의 semantic을 덮어쓰는 보정이 아니다.

| 입력 상태 | 화면 동작 |
| --- | --- |
| 원문 인용과 값이 같은 완전한 날짜·시각이고 날짜 정보만 빠짐 | 코드로 날짜 형식을 확인해 후보 제공 |
| 검증된 날짜 fact가 일정의 `valueFactKey`에 직접 연결됨 | 보호 상태가 아닌 일정의 변경 후 시작 시각만 자동 입력 |
| 선택한 준비 항목의 근거에 확인 가능한 날짜가 있음 | 사용자가 `마감으로 입력` 버튼을 눌러 선택 |
| 원문과 값이 다르거나 기존 날짜 metadata가 틀림 | 날짜 후보와 자동 입력에서 제외, 잘못된 metadata를 몰래 고치지 않음 |
| 직접 수정하거나 지운 입력 | 유지하고 자동 입력/선택 출처 표시 제거 |
| 원문·준비 항목·준비 방식 전환 | 선택 근거로 넣은 마감과 출처 표시를 함께 비움. 별도로 직접 쓴 값은 유지 |

끝 시각, 이동 시간, 가용 시간은 추측하지 않는다. 준비 마감은 역할을 추정해 자동 지정하지 않는다. 사용자가 저장한 준비 마감일과 다른 후보는 해당 준비 항목에 제안하지 않는다. 최종 확인과 기존 서버 검증은 그대로 필요하다.

## 지원 범위와 한계

날짜 정보가 없는 경우의 대체 처리는 **인용 전체와 표시 값 전체가 날짜·시각으로 구성된 경우**만 지원한다. 연도를 포함한 ISO 날짜, 한국어 연월일, `HH:mm`, 오전/오후 시·분을 읽는다. 양쪽 표현 방식이 달라도 정규화된 날짜·시각이 일치해야 한다. 실제 달력에 없는 날짜, 잘못된 시·분, 연도 없는 날짜, 상대 날짜, 범위, 여러 시각, 부정·취소 문구는 이 대체 처리의 대상이 아니다.

한국 시간 표시는 양쪽에 명시된 지원 표현만 인정한다. 다른 문장에 있는 시간대를 가져오거나 UTC/다른 지역을 한국 시간으로 바꾸지 않는다. 원문 인용의 저장 위치도 실제 원문과 일치해야 한다.

이미 구조화된 날짜는 기존 의미 검증을 통과해야 한다. 구조화 정보가 부분적으로 있거나 잘못된 경우 글자 해석으로 우회하지 않는다. 날짜 정보가 없고 인용이 일반 문장 전체인 경우도 이 좁은 대체 처리를 적용하지 않는다. 이런 입력은 여전히 직접 확인해야 한다.

## 검증의 구분

- 단위 검사: 완전한 한국어/ISO 날짜, 윤년·오전/오후, 시간대 양쪽 일치, 원문 위치, 잘못된 날짜·범위·상대 날짜·기존 metadata, 입력 불변성.
- DB 통합 검사: 제어한 모델 응답을 실제 Queue/core/D1 경로로 저장·승인·재조회한다. 원본 semantic은 null로 유지하면서 입력용 값이 생기고, 조회 후 snapshot/revision이 바뀌지 않으며 중복 Queue 전달이 모델을 재호출하지 않는지 확인한다. 실제 유료 AI 응답을 새로 받은 검사는 아니다.
- 브라우저 검사: 명확한 원문 날짜의 자동 입력, 준비 마감 선택, 직접 수정/비우기, 선택 전환과 출처 제거, 잘못된 날짜 후보 차단.
- 과거 실제 Gemini 응답 재현: 당시 실패 응답을 그대로 읽어 이번 입력 보완 효과를 확인한다. 기존 모델 평가의 `passed:false`는 그대로 보존한다. 이를 새로운 모델 정확도나 일반 성공률로 표현하지 않는다.

프롬프트·모델·공급자 요청·저장 형식·비용 정책이 바뀌지 않아 이번 검증에는 추가 유료 모델 호출이 필요하지 않다. 사람을 대상으로 한 시간 절감·구매 의향 검증은 별도 과제다.

## 실행 기록

실제 결과와 배포 버전은 `.omx/verification-date-normalization-2026-09-16.json`과 `PLANS.md` 최신 기록에서 확인한다. 원본 실패와 최종 로그는 `artifacts/date-normalization-2026-09-16/`에 보존한다.

기존 E2E의 원문은 9월 16일인데 기대 날짜는 10월 21일이던 fixture 불일치를 독립 리뷰 후 수정했다. 원문·인용을 10월 21일로 맞추고 근거 없는 시간대를 제거했으며, 승인·재시도 검증은 유지했다. 별도 적대 사례로 원문과 날짜가 다르면 후보가 나오지 않는지 확인한다. 이번 사용자 요청은 기존 실패 루프를 재설정하는 작업이 아니라, 원본을 보존하는 날짜 읽기 구조를 도입하는 새 범위다.
