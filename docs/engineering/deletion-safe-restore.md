# 이어짐에서 백업 복원 후에도 삭제를 지키는 방법

이어짐은 안내문에서 일정과 할 일을 정리하는 서비스다. 사용자가 작업 공간을 삭제한 뒤에도 과거 백업에는 원문과 파생 데이터, 대기 중이던 모델·캘린더·메일 작업이 남아 있을 수 있다. 백업을 그대로 복원하면 화면에 삭제한 자료가 다시 보이거나, 대기 작업이 다시 실행될 수 있다. 이번 변경의 목표는 **서비스를 복구한 뒤에도 사용자가 선택한 삭제 상태를 유지하는 것**이었다. [이어짐 서비스](https://ieojim.jungseongheon.org)

## 삭제 이력을 앱 데이터와 분리

삭제 표시를 앱 DB 안에만 두면 앱 데이터를 되돌릴 때 그 표시도 같은 시점으로 돌아간다. 작업 공간 식별자, 삭제 시각, 순번을 별도 D1에 기록하고, 앱 D1에는 어디까지 반영했는지 체크포인트를 남겼다. 복구 시 앱 D1만 되돌리고, 삭제 이력 D1은 최신 상태로 유지한다. [Cloudflare D1 Time Travel](https://developers.cloudflare.com/d1/reference/time-travel/)

1. **삭제 대상을 숨기고 이력을 기록.** 앱 D1에서 대상을 먼저 숨긴 뒤 별도 D1에 기록한다. 직접 삭제와 만료가 같은 경로를 사용한다. 이력을 기록한 뒤 정리가 중단되면 두 순번의 차이로 미반영 상태를 확인할 수 있다. 직접 삭제는 정리가 끝나고 순번이 일치한 뒤 성공을 응답한다.
2. **확인할 수 없으면 차단.** 이력 DB를 확인할 수 없거나 두 순번이 다르면 비공개 API는 503을 반환하고 Queue의 새 작업 실행과 일반 만료 처리도 차단한다. 복구 중 잠깐의 가용성을 포기하더라도 삭제한 내용의 노출이나 외부 작업 실행을 막는 편이 중요했다.
3. **삭제와 체크포인트 갱신을 함께 처리.** 유지보수 모드에서 밀린 이력을 순서대로 읽고, 앱 DB에서 대상 삭제와 적용 순번 갱신을 같은 트랜잭션에 묶는다. 재실행 시 이미 반영한 이력을 다시 적용하지 않는다. 순번이 같아진 뒤에도 검증을 마칠 때까지 유지보수 모드를 유지한다. [Cloudflare D1 batch 실행](https://developers.cloudflare.com/d1/worker-api/d1-database/#batch)

## 실제로 확인한 결과

| 환경 | 재현한 상황 | 확인 결과 |
| --- | --- | --- |
| 격리 환경 | 실제 D1 Time Travel로 앱 DB를 삭제 전 시점에 복원 | 원본·파생 데이터와 대기 작업이 복원됨. 앱 적용 순번 0, 별도 이력 최신 순번 2. |
| 격리 환경 | 순번 차이가 있는 상태에서 조회와 작업 실행 시도 | 비공개 HTTP 핸들러 호출 5건 모두 503. 실제 Queue가 전달한 작업 메시지 3건은 실행과 ACK 없이 차단. |
| 격리 환경 | 삭제 이력 재적용 후 다시 조회하고 이전 작업 ID를 새 메시지로 전송 | 삭제 대상 데이터 10개 범주 모두 0건. 재적용을 반복했을 때 추가 처리 0건. 삭제한 원본·파생 공간 조회와 원본 내보내기는 404, 유지한 공간 조회는 200. 이전 ID를 담은 메시지 3건은 실행 없이 ACK 처리됐고, 앱의 작업 재등록은 0건. |
| 공개 환경 | 합성 작업 공간 하나를 소유자가 직접 삭제 | 삭제 전 목록·상세·내보내기 정상. 삭제 요청 204. 삭제 후 상세·내보내기 404, 목록에서 제외. 앱 DB 대상 행 0건, 삭제 이력 1건. |
| 공개 환경 | 별도 합성 공간의 만료 시각을 과거로 설정하고 실제 Cloudflare Cron 실행 대기 | 만료 1건, 작업 재등록 0건. 앱 DB 대상 행 0건, 해당 삭제 이력 1건. 상세·내보내기 404, 목록에서 제외. 두 테스트 종료 후 앱 적용 순번과 이력 최신 순번 모두 2. |

격리 환경에서는 복원으로 데이터가 돌아온 상태부터 확인한 뒤 차단과 재적용을 시험했다. 공개 환경에서는 직접 삭제와 예약 만료를 각각 합성 데이터로 검증했다. 이력 재적용 후 Queue 시험은 이전 작업 ID를 담은 새 메시지를 사용했다. [Cloudflare Queue 전달 방식](https://developers.cloudflare.com/queues/reference/delivery-guarantees/) · [Cloudflare Cron Triggers](https://developers.cloudflare.com/workers/configuration/cron-triggers/)

## 운영 기준

공개 배포 전에 앱 DB의 시점 복원 기준을 기록하고 암호화 SQL 백업을 만들었다. 복호화한 백업의 해시를 원본과 대조하고, SQLite에서 무결성과 외래 키를 검사했다. 실제 시점 복원 시험은 합성 데이터가 있는 격리 환경에서 수행했다.

복구할 때는 먼저 비공개 요청과 Queue 소비를 멈추고, 앱 DB만 복원한다. 최신 삭제 이력을 다시 적용한 뒤 순번 일치, 삭제 대상 조회 차단, 기존 작업의 실행 여부를 확인하고 서비스를 재개한다. 롤백도 삭제 이력을 읽고 차단할 수 있는 버전을 기준으로 한다. 복원 가능한 가장 오래된 백업에 필요한 삭제 이력을 보존한다. [Cloudflare Workers 버전 롤백](https://developers.cloudflare.com/workers/versions-and-deployments/rollbacks/)

검증 범위는 작업 공간 삭제와 만료, 같은 소유자의 파생 공간, 연결된 내부 데이터와 대기 작업이다. 계정 삭제와 외부 서비스에서 이미 완료된 작업의 취소는 별도 범위다.
