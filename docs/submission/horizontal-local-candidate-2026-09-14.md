> 새 안내가 올 때마다 일정·비용·준비 목록을 다시 맞추며 확정한 결정과 완료 기록을 놓치는 문제를 해결합니다.

AI 활용 방식 및 결과 (공백·문장부호 포함 261자, 500자 이내):

> 개발에는 Codex를 사용해 설계·구현·독립 리뷰·회귀 검증을 반복했습니다. 서비스의 Gemini는 안내문의 변경 사실과 원문 근거를 구조화합니다. TypeScript 엔진은 근거·계산·기준 버전·사용자 상태를 검증하고, 고정 일정 변경과 완료 항목 삭제는 사용자의 선택을 거쳐 원자적으로 저장합니다. 미팅 준비·과제 공지·여행 안내가 같은 엔진을 사용합니다. 합성 체험과 실제 AI 호출을 구분하며, 직접 쓴 메모와 준비 설정을 보존하고 재검토할 부분을 표시합니다.

도구 목록은 실제 사용한 React·Gemini를 선택하고 Codex는 AI 활용 본문에 적는다. 추가 입력이 가능하면 TypeScript, React/Vite, Hono, Cloudflare Workers·D1·Queues, Better Auth, Zod, Three.js/React Three Fiber, Playwright/Vitest를 기재한다. 정식 서비스 링크는 `https://ieojim.jungseongheon.org`다. 공개 기능 설명은 배포 확인 시점에 다시 대조한다.

## 로컬에서 확인할 흐름

1. `http://127.0.0.1:5173/`에서 업무·학업·생활 소개와 `내 안내로 시작하기`를 확인한다. 작업 이름·목적을 정해 `만들기`를 눌러야 빈 실제 작업 공간을 만든다. 페이지 이동만으로 원문·예시를 저장하지 않는다.
2. 첫 화면의 `미팅 변경 검토하기`를 누른다. 미팅 14→16시, 자료 마감 9/17→9/16, 장소 변경과 원문 근거를 확인한다. `사전 보고`와 `인쇄본 확인`에서 각각 선택한 뒤 `미팅 선택 결과 보기`를 누른다. 이 결과는 브라우저 메모리 전용이며 저장되지 않는다.
3. 업무·프로젝트 카드 → `고객 미팅 변경 체험 시작`으로 실제 합성 작업 공간을 만든다. `고객 미팅 정정 안내 불러오기` → `변경 검토`에서 두 충돌을 선택하고 `검토한 변경 반영`을 누른다. 새로고침하여 저장된 일정·완료 상태·준비 마감·예상 시간을 확인한다. 공유할 계획 미리보기는 현재 저장된 값을 사용한다.
4. 학업·과제 카드 → `과제 예시 열기` → `과제 마감 변경 체험`에서 10/3→10/10 변경을 검토한다. 생활·약속 카드 → `출발 전날 복합 체험 시작`에서는 인원·비용 변경과 잠근 저녁·완료 항목을 확인한다. 세 예시는 각각 별도 작업 공간이다.

합성 예시는 실제 변경·승인·저장 엔진을 실행하지만 모델을 호출하지 않는다. 내 안내문으로 AI 정리를 요청하면 실제 Gemini와 서비스 예산을 사용한다. 자동 메일 수집, 여러 작업 공간을 합친 일정 최적화, 외부 캘린더 적용은 구현하지 않았다.
