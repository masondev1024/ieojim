# September 19 UI critique and repair

The user requested multiple independent critics and actual local UI repairs. The root captured 21 states across introduction, home, recovery, blocked recovery, workspace, source, login and settings. Before images and DOM measurements are in `artifacts/ui-critic-2026-09-19/before/`. No horizontal overflow was found, but that alone does not establish a usable design.

## Observed problems and design decisions

1. Recovery progress text starts at x=0 while its neighbours use a centred 1160px container. Align the same shell at 320, 390, 768, 1024 and 1440px. Differentiate completed, waiting, pending and attention states without suggesting unperformed external work.
2. The recovery hero repeats the notice; the actual changed appointments are below the fold. Replace the repeated notice card with before/after values derived from the calculated events, protected count, and an accessible collapsed source/evidence disclosure. Show the result in the first desktop viewport. Dirty or infeasible plans must show their condition, not a successful change list.
3. Mobile before/after columns are too narrow despite passing overflow tests. At <=560px show one full-width timeline with explicit `조정안 보기` / `변경 전 보기` selection. Keep both timelines side by side on desktop. Both retain every event and the original values. Blocked plans always expose the unchanged baseline.
4. The unavailable email form adds a long wall of controls. Place only its composer and exact approval in a native, initially closed `이메일 작성·확인` disclosure. Keep connection status, Calendar controls, current recheck results and failures visible. Opening a disclosure never sends a request or grants permission. Fields stay before exact approval; every existing dispatch guard stays intact.
5. Distinguish the primary save action from the local-only preview approval; keep explicit saving and approval separate. Reduce repeated explanation and card chrome. Preserve the warm-paper/SUIT/forest palette, visible focus, 44px controls and enlarged-text reflow.
6. Verify other captured surfaces and apply bounded layout/copy corrections where critics find concrete defects. No new framework, paid API, server/migration, or external execution is part of this UI repair.
   - Mobile landing repeated the same example in three summary rows before the interactive card. Keep that desktop summary but omit its mobile duplicate; put the existing explicit demo start directly below its synthetic/no-save explanation. No demo logic or claim changes.
   - Home's mobile topbar rule lost a same-specificity cascade to the general workspace stylesheet, leaving the brand on a separate line and a redundant guest badge beside the guest account button. Scope the home rule explicitly, keep its account control, and retain the guest/AI/retention information in the existing start form and copy.
