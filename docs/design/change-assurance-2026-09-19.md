# 변경 반영 후 확인 루프 — 2026-09-19

## 목표와 범위

사용자가 승인한 일정이 외부 캘린더에서도 유지되는지 확인한다. 변경 요청 입력, 내부 승인, 외부 실행, 이후 확인을 서로 다른 상태로 보여준다. Spark/Aside 조사에서 도출한 방향을 기존 TypeScript/Workers/D1 구조 위에 구현한다. 범용 브라우저 제어·자동 결제·전체 메일함 수집은 이번 완료 범위가 아니며 구현한 것처럼 표시하지 않는다.

사용자는 9월 20일 전 구현을 요청했다. 구현과 로컬 검증은 승인되었으며 커밋·푸시·배포·실제 메일 발송은 별도 권한 경계를 유지한다. 기존 테스트의 기대값과 검증 설정을 보존하고 새 회귀 테스트를 추가한다.

## 구현 순서

1. 승인한 작업과 실제 반영 결과를 구분하는 완료 상태를 보여준다. 근거 원문, 보호한 결정, Calendar의 실행 당시 확인 기록은 유지한다.
2. 명시적 버튼으로 복사한 안내를 미리 보고 현재 원문 초안으로 가져온다. 초안 덮어쓰기 확인, 권한 거절, 길이 제한, 늦은 응답 및 작업 공간 전환을 처리한다. 가져오기 자체는 저장이나 AI 호출이 아니다.
3. 완료한 Calendar 실행의 정확한 이벤트를 다시 읽는다. 일치·외부 수정·삭제·조회 실패·기준 변경을 구분하고, 과거 실행 성공과 현재 확인 결과를 분리한다.
4. 사용자가 켠 경우에만 15분 간격, 최대 24시간 동안 같은 승인 건을 읽기 전용으로 확인한다. 만료·연결 해제·기준 변경·외부 변경 발견 시 중지한다. 일시적 조회 실패는 한도 안에서 다음 확인을 예약하고 3회 연속 실패 시 중지한다.
5. 사용자에게 무엇을 확인했는지, 무엇을 수정하지 않았는지, 다시 어떤 결정이 필요한지 보여주고 전체 흐름을 검증한다.

브라우저 자동 조작은 도입하지 않는다. 이번 입력 보조는 사용자가 고른 텍스트의 명시적 가져오기다. 반복 정책은 위 읽기 전용 확인 한 가지로 제한한다. 변경 감지 후 자동 재승인·자동 덮어쓰기·자동 메일 발송은 없다.

## 데이터 흐름과 불변 조건

`사용자가 고른 원문 → 기존 AI 사실 추출/검증 → 정확한 버전 승인 → 기존 outbox → provider readback → 별도 확인 기록 → 필요 시 사용자 재검토`

- 기존 실행 기록의 `verified`는 당시 성공 기록이다. 이후 외부 수정 때문에 이를 지우거나 실패로 덮어쓰지 않는다.
- 새 확인은 승인 action ID, workspace/source/condition revision, 연결 ID/version에 묶인다. 현재 기준과 다르면 외부 조회 또는 결과 채택을 중단한다.
- 확인은 이어짐이 만든 전용 캘린더의 승인한 이벤트만 조회한다. 전체 계정 탐색, primary 쓰기, Gmail 읽기, 새 OAuth scope는 없다.
- 네트워크 실패는 변경 없음이 아니다. 확인한 시각과 범위를 표시한다. `etag` 변화도 검토가 필요한 변경으로 취급한다.
- 늦게 돌아온 이전 확인 결과가 새 설정/새 승인/연결 해제 이후 결과를 덮어쓰지 않도록 claim token과 조건부 갱신을 사용한다.
- 중복 cron과 중복 버튼은 하나의 claim만 실행한다. 외부 조회는 재시도 가능하지만 외부 쓰기나 유료 모델 호출을 이 루프에서 수행하지 않는다.
- 반복 확인은 사용자 활동이나 보관 기간을 연장하지 않는다. 7일 미사용 만료, 삭제, 계정 소유권 경계는 유지한다.
- 기록과 조회 개수에 상한을 둔다. 로그는 ID·상태·개수만 남기고 원문, 이벤트 내용, 토큰은 남기지 않는다.

## 검증 및 완료 조건

- 변경/삭제/조회 실패/연결 해제/승인 기준 변경/중복 실행/취소와 진행 중 확인 경합을 D1 통합 테스트로 확인한다.
- 확인 중 provider insert/update/send가 0회임을 검증한다. 반복 확인을 켜기 전에는 자동 조회하지 않는다.
- 복사한 내용은 미리보기에서 검토하고 명시적으로 가져와야 하며 기존 초안과 작업 공간 이동을 보호한다.
- 새 화면의 실제 API 계약, 오류 표시, 키보드와 모바일 폭을 브라우저에서 확인한다. mock provider 검증과 실제 Google 재검증을 구분한다.
- `npm run verify`, 전체 Chromium 회귀, 독립 코드 리뷰를 통과한 범위만 완료로 기록한다.
- 운영 적용에는 additive migration, 배포 순서, 중지/rollback, 조회량·실패 관측 runbook을 준비한다. 실제 remote migration/deploy 전에는 별도 승인이 필요하다.

## 후속 범위

외부 메일/공지의 능동 수집, 여러 자료·사람·실행 대상을 잇는 범용 의존 관계, 제한된 브라우저 executor, 외부 작업의 보상 실행은 별도 단계다. 본 변경은 이 기능들의 완료나 Spark/Aside보다 높은 자동화 성능을 주장하지 않는다.
