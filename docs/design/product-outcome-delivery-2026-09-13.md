# 이어짐 제품 결과 전달 구현 기록

2026-09-13. 여행 총무가 새 안내를 받았을 때 실제로 확인하고 전달할 수 있는 결과물을 앞에 세웠다. 범위는 제품 첫인상, 명시적 여행 시작, 현재 저장된 계획 미리보기/복사, 그리고 브라우저 검증 안정화다. 결제, 외부 알림, 새 백엔드 계약, 새 유료 모델 호출은 포함하지 않았다.

## 실제 가치 흐름

첫 화면은 추상적인 작업 공간 소개 대신 여행 변경의 결과를 바로 보여준다. 합성 예시는 “4명에서 3명으로 변경”, “총액 900,000원 유지”, “1인 비용 225,000원 → 300,000원”, “DAY 02 19:00 저녁 예약 유지”를 한 화면에서 드러낸다. 사용자는 검토 화면과 단체방 공유용 초안을 직접 전환해 볼 수 있다.

이 흐름의 목적은 모델 기능을 과시하는 것이 아니라 총무의 다음 행동을 줄이는 것이다. 새 원문이 들어왔을 때 어떤 값이 바뀌었고, 어떤 결정은 보호됐으며, 지금 무엇을 동행자에게 보내면 되는지 보이게 했다. 첫 화면의 예시는 합성 자료로 표시하며, 탐색만으로 API 쓰기나 모델 호출이 일어나지 않는다.

## 명시적 시작과 예시

`/app?template=travel`은 여행 계획을 만들기 쉬운 초안 상태로 홈을 연다. 사용자가 작업 이름과 목적을 확인한 뒤 **만들기**를 눌러야 작업 공간이 생성된다. URL 진입이나 템플릿 선택만으로 데이터베이스에 쓰지 않는다.

`/app?example=travel`은 실제 자료가 없는 사용자를 위해 합성 여행 체험을 먼저 보여준다. 여기서도 저장된 합성 예시 버튼을 명시적으로 눌러야 체험이 시작된다. 개인 초안, 직접 설정, 기존 작업 목록은 계속 남아 있어 처음 방문자와 재방문자가 같은 홈에서 각자의 일을 이어갈 수 있다.

## 현재 저장된 계획

계획 패널에는 **현재 저장된 계획** 미리보기와 복사 동작을 추가했다. 이 기능은 소유자 범위의 export를 읽고, 스키마·체크섬·workspace ID·현재 content revision을 확인한 뒤 저장된 값만 문장으로 만든다. 검토 중인 제안이나 아직 승인하지 않은 변경은 복사 문안에 섞이지 않는다.

메모는 기본으로 제외한다. 사용자가 **메모 포함**을 선택한 경우에만 포함하며, 수동으로 고친 값은 그대로 보존한다. 브라우저가 클립보드 쓰기를 거부해도 미리보기 textarea가 남아 사용자가 직접 선택해 복사할 수 있다. 닫기와 작업 전환은 진행 중인 export 요청을 무효화해 늦게 도착한 응답이 다른 workspace나 revision의 내용을 덮지 못하게 한다.

현재 저장된 계획을 기준으로 삼은 이유는 데이터 품질 때문이다. 원문 관찰값은 변경 후보와 근거를 제공하지만, 사용자가 고정한 결정, 수동 수정, 완료 상태, 승인된 계산 결과를 모두 대표하지 않는다. 반대로 저장된 계획은 이미 적용된 결정의 현재 상태이며, 동행자에게 보낼 문장에는 이 커밋된 상태가 더 적합하다. 그래서 원문은 증거로 남기고, 전달 문안은 현재 persisted plan에서 만든다.

기존 승인 변경 복사 기능은 더 엄격한 계약을 유지한다. 현재 revision이 `apply_changeset`이고 바로 이전 snapshot이 있을 때만 before/after 변경 문안을 만든다. 전체 계획 복사는 이 계약을 완화하지 않고, 별도의 현재 저장본 복사로 분리했다.

## 검증 안정화

브라우저 테스트 서버는 각 실행마다 빌드 산출물을 별도 runtime assets 디렉터리에 복사해 제공한다. 이렇게 하면 나중에 시작된 빌드나 병렬 실행이 현재 E2E Worker가 서빙하는 정적 파일을 바꾸는 문제를 줄일 수 있다. 테스트 격리는 제품 기능은 아니지만, 회귀 검증의 신뢰도를 높이는 운영 품질 작업이다.

정적 리뷰에서는 현재 계획 문안이 pending proposal을 읽지 않는 점, note opt-in, stale response 방지, approved-change invariant 유지, URL/template 진입의 무쓰기 동작, owner-scoped export 경로를 확인했다. 최종 검증 기록은 PLANS.md 및 .omx/verification-product-desire.json 참조.

## 남은 경계

이번 작업은 사람이 실제로 비용을 지불할 의향을 검증하지 않았다. 합성 예시는 제품 이해를 돕는 장면이지 수요 검증이나 매출 근거가 아니다.

보관 정책은 여전히 7일 미사용 만료를 전제로 한다. 장기 보관, 결제, 계정 전체 삭제, billing/account-wide erasure는 완료 범위가 아니다. 실제 단체방·메일·메신저 발송도 하지 않는다. 복사는 로컬 클립보드 동작이며, 공개 링크나 외부 알림 전달을 약속하지 않는다.

새 백엔드, 새 모델 계약, 새 유료 호출 없이 기존 export와 현재 UI 흐름 안에서 구현했다. 운영 관점에서는 이 선택이 비용과 장애 범위를 줄이지만, 외부 공유·유료 보관·협업 제품으로 확장하려면 별도 권한 모델, 감사 로그, 보존 정책, 청구 수명주기 설계가 필요하다.
