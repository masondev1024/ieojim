# 이어짐 — 서비스 경험과 상용화 방향

2026-09-09 사용자 요청: 외부 사용자 모집과 외부 알림 연결을 추후로 미루고, 3D와 프론트엔드 디자인을 개선해 회원가입과 실제 유료 판매가 가능한 서비스로 발전시킨다. 이 문서는 설계 결과이며 새로운 UI, 인증, 결제가 구현됐다는 기록이 아니다. 구현 기준은 루트 DESIGN.md다.

## 현재 관찰

src/client/main.tsx는 첫 화면에 생성 폼, 예시, 원문 입력, 결과, 검토, 이력, 삭제를 함께 노출한다. App.css의 3열/중첩 테두리 구조에서 사용 목적과 다음 행동의 우선순위가 약하다. 모바일은 대부분 패널을 수직으로 쌓는다. 기능 검증에는 유효했지만 처음 방문한 사람이 가치를 발견하고 반복 사용하는 경험은 부족하다. 현재 브라우저와 합성 예시 스크린샷을 확인한 설계 판단이며 사용자 조사 결과는 아니다.

현재 계정은 회원 계정이 아니라 익명 소유권 쿠키다. 가입·로그인·다른 기기에서 접근·결제는 아직 없다. 이전 운영 검증과 이 상용 제품 범위를 구분한다.

## 추천하는 첫인상과 핵심 장면

첫 화면은 짧은 소개와 실제 체험 진입이다. 문구는 **“계획은 바뀌어도, 내 결정은 그대로.”**를 추천한다. 어두운 소개 화면에 흰색 입체 원문/계획 카드를 배치하고 실제 작업 화면은 밝고 읽기 쉽게 만든다.

1. 여행 인원 원문이 4명에서 3명으로 바뀐다.
2. 총 고정비 900,000원은 유지되고 인당 금액이 225,000원에서 300,000원으로 바뀐다.
3. 관련 항목으로 변경이 전달되는 모습을 짧은 움직임으로 보여준다.
4. 고정한 둘째 날 19:00 저녁 일정과 완료 항목은 보존 상태로 남는다.
5. 실제 제품에서는 근거와 변경안을 검토하고 승인한 뒤 저장 성공 시 최종 상태를 표시한다.

원문 → 사실 → 계산/항목의 실제 관계가 있을 때만 영향 연결선을 그린다. 함께 보이는 고정 일정이 인원 변경의 종속 항목인 것처럼 표현하지 않는다. 시안은 공간감/색/위계의 참고이며 실제 의존 그래프, 문구, 버튼 활성화는 코드 계약이 결정한다.

3D는 소개 화면의 한 장면과 선택적 “변경 흐름 보기”에 집중한다. 기본 편집과 승인은 DOM 화면을 제공한다. 로그인·결제 버튼은 실제 연결 전까지 활성 서비스처럼 노출하지 않는다.

## 구현 순서와 완료 조건

| 단계 | 작업 | 완료 조건 |
| --- | --- | --- |
| D1 | 브랜드, 소개, 작업 공간 홈, 안내형 첫 입력 | 실제 게스트 진입 가능; 가짜 가입/요금 버튼 없음; 저장된 작업 복귀 |
| D2 | 계획 캔버스, 원문/이력 탐색, 상황별 변경 검토 | 편집·고정·완료·근거·승인·복원·삭제 회귀 통과; 모바일/키보드 가능 |
| D3 | 제품 의미와 연결된 3D 및 UI 모션 | 지연 로드, 정지/재생, reduced-motion, WebGL 실패 대체; 성능 예산 측정 |
| A1 | 실제 인증과 게스트 작업 이관 | 로그인/로그아웃/다른 기기, 계정 격리, 중복/부분 실패 없는 이관 |
| A2 | 회원 보존, 설정, 내보내기/삭제, 사용량 | 회원 데이터에 게스트 만료가 잘못 적용되지 않음; 표시 정책과 서버 일치 |
| B1 | 요금제와 실제 결제 수명주기 | 서버 권한 판정, 서명 검증, 중복/역순 이벤트, 실패·취소·환불·대사 검증 |

결제 가능 의사를 새 판매자 계정, 구독 플랜, 실제 수금이나 인프라 지출 승인으로 해석하지 않는다. D1–D3는 외부 사용자 모집이나 webhook 발급에 의존하지 않는다.

## 도구와 구매 판단

공식 문서를 2026-09-09 확인했다. 필수 유료 구매는 현재 없다.

| 도구 | 역할 | 판단 |
| --- | --- | --- |
| Three.js + React Three Fiber | TypeScript/React에서 직접 관리하는 3D | 기본안. 기존 React 19와 맞는 버전 조합 확인 |
| Motion | 패널/카드/상태 전환 | 공개 라이브러리로 시작. 기본 모션에 유료 구독 불필요 |
| Motion AI Kit / Motion+ | 공식 스킬·문서/예제 MCP·모션 성능 점검 | 추가 구매 우선 후보. 무료 문서/지침부터 쓰고 예제/유료 도구 필요 시 확장 |
| Figma | 화면 비교, 디자인 파일/토큰 전달 | 선택 사항. 코드 기반 첫 구현에 유료 좌석 필수 아님 |
| Spline | 시각 편집하는 3D 장면 | 구체적인 외부 장면 필요 시 검토. 현재 Code/Self-hosted export는 Enterprise 항목이므로 저가 플랜만으로 필요한 배포 확보를 가정하지 않음 |
| 맞춤 3D/브랜드 자산 | 고유 그래픽과 타이포/아이덴티티 | 도구 여러 개보다 특정 결과물에 예산을 배정할 선택지. 편집 원본·상업 사용 조건·최적화 가능한 자산 확보 |

React Three Fiber는 React의 Three.js 렌더러이고 React 19 대응 메이저 조합을 명시한다. [공식 저장소](https://github.com/pmndrs/react-three-fiber)

Motion은 공개 라이브러리로 시작할 수 있고 Motion+는 개인 일회성 구매/팀 좌석을 구분한다. 확인한 페이지에서 정확한 결제 금액이 동적으로 숨겨져 있어 추정 가격을 쓰지 않았다. [Motion+](https://motion.dev/plus)

Motion AI Kit는 무료 문서 검색/기본 지침과 유료 예제·성능 도구를 구분한다. 추가 MCP/스킬은 OMX를 대체하는 상위 컨트롤러가 아니라 모션 작업에 한정한다. 설치 시 프로젝트 범위를 우선하고 전역 설정은 별도 지시 없이 바꾸지 않는다. [공식 AI Kit 문서](https://motion.dev/docs/ai-kit)

Spline의 export 요금 구분 때문에 현재는 직접 구현을 우선한다. 구매 전에 실제 필요한 export와 배포 조건을 확인한다. [공식 가격표](https://spline.design/pricing)

Figma는 무료 시작 플랜을 제공한다. 디자인 파일 협업 단계에서 MCP/유료 좌석 필요성을 판단한다. [공식 가격표](https://www.figma.com/pricing/)

OS의 모션 감소 설정에 따라 패럴랙스/카메라 이동을 줄인다. [공식 Motion API](https://motion.dev/docs/react-use-reduced-motion)

## 실제 계정과 결제의 설계 경계

기존 브라우저의 작업 공간 집합과 로그인 계정을 사용자에게 확인시킨 뒤, 재시도 가능한 하나의 이관 작업으로 처리하는 방식을 추천한다. 이관 도중 생성/승인 중인 작업, 로그인 세션과 게스트 쿠키 공존, 다른 계정 재로그인, 만료 작업, 부분 실패와 중복 요청을 검증한다.

익명 체험의 7일 만료와 회원 저장 정책은 분리해야 한다. 정책과 DB/정리 작업을 바꾸기 전에는 장기 보관을 약속하지 않는다. 이관해도 과금 원장을 초기화하거나 사용자 한도를 회피할 수 없어야 한다.

결제 상태는 브라우저 성공 문구가 아니라 서버가 검증한 이벤트와 대사 결과로 판정한다. 중복/지연/역순 이벤트, 결제 실패와 취소를 견디는 권한 상태가 필요하다. 판매자 국가·사업 형태·통화와 요구 기능을 정한 뒤 공급자를 고른다. 특정 결제 사업자는 아직 확정/연결되지 않았다.
